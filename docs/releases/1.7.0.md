# v1.7 candidate implementation and validation

Candidate: **1.7.0-rc.1**, prepared **2026-10-26**. This record covers the
cryptography experiment work. No tag, GitHub release or NuGet publication has
been created. See the [experiment guide](../cryptography.md),
[original research](../cryptography-research.md) and [changelog](../../CHANGELOG.md).

## Implemented scope

- Internal BB84/noisy-BB84 workflows with independent measurement histories,
  disclosed-bit statistics, per-basis Hoeffding intervals and idealized bounds.
- CHSH correlations with explicit measurement settings and one-sided noise.
- Reversible toy-cipher Grover oracle with work/scratch uncomputation.
- Bounded small Shor order finding with controlled modular permutation synthesis,
  inverse QFT and verified classical continued-fraction postprocessing.
- Separate nonpackable net10.0 platform PQC lab: ML-KEM and ML-DSA, selected NIST
  known-answer cases, imported keys, tampering and AEAD checks, and raw timings.
- Explicit opt-in SLH-DSA experimental helper; unsupported provider reporting.

No cryptography declaration is added to SDK PublicAPI inventories. The experiments
remain repository tooling. Libraries keep net9.0, 1.0.0.0 assembly binding and the
reviewed published 1.0.0 package-validation baseline. No new runtime package or
backend port is introduced. The only new project is the separately justified
net10.0 PQC tooling boundary; only net10.0 tests reference it.

The checkout already contained CPU-performance changes and continued receiving
those edits during this work. Validation below concerns the current combined
working tree; it is not evidence for a clean tagged cryptography-only commit.
Those changes and their API inventory must be reviewed separately before promotion.

The accompanying CPU work explicitly adds EnableGateBlocking and EnableAvx512
get/init accessors to Infrastructure's Unshipped inventory; shipped declarations
remain intact. See the [CPU analysis](../performance-analysis.md) and
[AVX-512/CUDA validation](../avx512-cuda-performance.md) for scope, raw measurements
and current combined-tree validation. The cryptography-only statement above does
not imply that these separate CPU option additions are absent from the candidate.

## Numerical evidence

The recorded scalar Release run gives full intercept-resend BB84 QBER 24.962%,
against analytic 25%, and zero ideal errors without interception/noise.
CHSH gives S=2.81100 with estimated SE=.01423 against 2*sqrt(2).
The toy verifier finds key 5 with exact Born probability .9453125 (121/128),
using seven physical qubits and 83 gates. Small Shor uses 14 physical qubits and
633 gates; its counting outcomes are {0:137,64:122,128:146,192:107} and it recovers
3 and 5. All of these are educational examples with explicit bounds.

## Remaining scope

The BB84 tool does not reconcile or privacy-amplify candidate bits into a secure
key, nor model authentication, photon loss or physical source/detector attacks.
The toy cipher is trivially invertible, and Shor's permutation compiler accepts
only odd N<=15. The local KEM/HKDF/AEAD check is not an authenticated network
protocol or a hybrid combiner. SLH-DSA needs a supporting native provider for
execution. No production cryptographic security level or attack date is inferred
from these experiments or measurements.
