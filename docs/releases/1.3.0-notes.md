# QuantumMatter 1.3.0

QuantumMatter 1.3 adds a separate dynamic-circuit workflow for mid-circuit
measurement, classical feedback and qubit reset while preserving the existing
unitary, noise and backend contracts.

## Install

Use matching package versions; Core is included transitively:

```sh
dotnet add package QuantumMatter.Application --version 1.3.0
dotnet add package QuantumMatter.Infrastructure --version 1.3.0
```

The [release record](1.3.0.md) tracks publication and validation evidence.

## Changes

- Build finite DynamicCircuit programs from snapshotted unitary segments.
- Measure ordered qubit selections into explicit classical destinations, including overwrite semantics.
- Execute unitary segments when a classical mask/value condition matches.
- Reset one qubit using measurement and conditional X, preserving the correct spectator ensemble.
- Execute a fresh quantum/classical history per shot and return immutable classical counts.
- Inspect one conditional trajectory's state and classical outcome without implicit final readout.
- Consume new APIs through an isolated dynamic package sample alongside observation and baseline consumers.

The 22 additive declarations bring the shipped API inventory to 240, preserving all
218 existing declarations. Library assets remain net9.0 for .NET 9/10 consumers;
assembly binding version stays 1.0.0.0 and file version is 1.3.0.0. No new runtime
dependency or backend interface is introduced.

## Conventions and limits

Registers contain 1–30 quantum/classical bits. Bit zero is least significant and
classical labels print the highest bit first. Measurements overwrite mapped bits;
unwritten bits remain zero. Run counts final classical memory and does not add
implicit quantum readout or return an ensemble ket.

Classical decisions and measurements run on the host. CUDA transfers at each
executed unitary-segment boundary. Loops, arbitrary classical expressions,
noise/dynamic composition and device-resident feedback are outside this release.
CPU support covers Windows/Linux x64; CUDA support covers Windows x64, with Linux
CUDA experimental. See the [dynamic guide](../dynamic-circuits.md),
[API additions](../api/1.3.0.md) and [compatibility policy](../compatibility.md).

## Validation

The implementation candidate passes all eight Windows/Linux runtime/configuration
jobs. Local hardware-enabled Debug/Release suites pass 734 tests per runtime on
an RTX 4070 Ti SUPER. CPU-only suites pass 653 tests plus one explicit hardware skip.
Tests force all four teleportation branches and compare complex receiver amplitudes;
independent dense Kraus matrices and exact branch enumeration verify reset and feedback.
Fresh package consumers and unchanged 1.0.0-compiled consumers pass on .NET 9/10,
including real CUDA. Stable promotion passes all eight CI jobs. The tagged-source
publication workflow passes Windows/Linux validation and uploads all three
packages and symbols through OIDC. Fresh public-feed baseline, observation and
dynamic consumers pass on .NET 9/10 with CUDA and the exact source commit verified.
The release record contains the publication evidence and reproduction commands.
