# QuantumMatter 1.1.0

QuantumMatter 1.1 adds full .NET 9/10 validation and compatibility checks against
the published 1.0.0 SDK. The libraries retain net9.0 assets and all 211 shipped API
declarations; existing mathematical conventions and simulator behavior are preserved.

## Install

Use matching package versions; Core is included transitively:

```sh
dotnet add package QuantumMatter.Application --version 1.1.0
dotnet add package QuantumMatter.Infrastructure --version 1.1.0
```

All three packages are published on nuget.org. The [release record](1.1.0.md)
contains publication and fresh public-feed verification evidence.

## Changes

- Build with the .NET 10 SDK and run the full xUnit suite on .NET 9 and .NET 10.
- Windows/Linux CI explicitly covers both runtimes in Debug/Release and uploads TRX results.
- CUDA hardware suites run on both runtimes sequentially when enabled.
- Package validation compares compiled APIs with published 1.0.0, including parameter names.
- Consumers compiled against published 1.0.0 run with replacement 1.1 assemblies
  without recompilation; hashes guard their binaries and dependency manifests.
- Runtime/version guards verify the actual runtime and loaded SDK assemblies.
- Public-feed validation can select an explicit package version.

The 1.x assembly binding version remains 1.0.0.0; the file version is 1.1.0.0.
No new runtime package dependency or compatibility suppression is introduced.

## Validation and support

Local Windows Debug/Release suites pass 666 tests per runtime including real CUDA
on an RTX 4070 Ti SUPER. CPU-only CI passes 587 cases per runtime with an explicit
hardware-suite skip. Both runtimes pass fresh and baseline-compiled CPU/CUDA
consumer checks. An intentional binary break is rejected with CP0002.

The tagged-source workflow passes Windows/Linux validation and OIDC publication.
Fresh nuget.org-only consumers pass CPU and real CUDA checks on .NET 9 and .NET 10;
all three packages identify the exact release commit.

Libraries support .NET 9/10 applications through the same net9.0 asset. CPU targets
are Windows/Linux x64; CUDA support is Windows x64, with Linux CUDA experimental.
See the [compatibility policy](../compatibility.md) for framework lifecycle,
precision, ownership, resource limits and reproducibility guarantees.
