## Scope

Use the .NET 10 SDK to build the existing net9.0 libraries and the full xUnit suite
for net9.0 and net10.0. Both suites exercise the same library assets on their actual
target runtimes; tests reject unintended major-version runtime roll-forward or
retargeted library assets. No simulator algorithms, mathematical conventions,
public signatures, assembly version or shipped API declarations change.

The Windows/Linux CI matrix covers Debug/Release and both runtimes explicitly.
Release jobs also verify portable CPU fallbacks and package consumers. Hardware
validation runs both suites sequentially so they share one physical GPU without
competing framework runs. The SDK and both runtimes must be installed.

## Compatibility checks

All three packages enable SDK package validation against their published 1.0.0
baseline, including parameter-name compatibility. Additive APIs remain possible;
no compatibility suppressions are introduced. The shipped 211-declaration API
inventory remains the source-level contract.

Test-Packages.ps1 additionally compiles a consumer against nuget.org's 1.0.0
packages in an isolated cache, then replaces only the three SDK DLLs with the
freshly packed candidate DLLs. The consumer DLL and baseline dependency manifest
must retain their original hashes. The app verifies that all three loaded SDK
assemblies report the candidate version, and exercises CPU, algorithms, noise,
budgets, cancellation and optional real CUDA without recompiling the consumer.
The consumer source intentionally uses only APIs available in 1.0.0.

References: [SDK baseline package validation](https://learn.microsoft.com/en-us/dotnet/fundamentals/apicompat/package-validation/baseline-version-validator),
[package validation properties](https://learn.microsoft.com/en-us/dotnet/core/project-sdk/msbuild-props#package-validation-properties).

## Reproduction

```powershell
dotnet restore QuantumMatter.sln
dotnet build QuantumMatter.sln --no-restore -c Debug -p:EnableCudaTests=true
dotnet test QuantumMatter.sln --no-build --no-restore -c Debug -p:EnableCudaTests=true
dotnet build QuantumMatter.sln --no-restore -c Release -p:EnableCudaTests=true
dotnet test QuantumMatter.sln --no-build --no-restore -c Release -p:EnableCudaTests=true
dotnet format QuantumMatter.sln --no-restore --verify-no-changes
./scripts/Test-Packages.ps1 -Configuration Release -SkipBuild -EnableCuda
./scripts/Test-Packages.ps1 -Configuration Release -SkipBuild -ConsumerFramework net10.0 -EnableCuda
```

Omit EnableCudaTests/EnableCuda on CPU-only machines. Those runs explicitly skip
the hardware suite and do not establish CUDA conformance. To run only one runtime,
use dotnet test tests/QuantumMatter.Tests/QuantumMatter.Tests.csproj --framework
net9.0 (or net10.0) with the desired configuration and hardware flags.

Test-PublishedPackages.ps1 accepts -PackageVersion so prior releases can be checked
independently of the current checkout version. Libraries retain
net9.0; no separate net10.0 package asset or performance improvement is claimed.

Verify the release independently with fresh caches and no
local feed, including the exact tagged-source metadata:

```powershell
./scripts/Test-PublishedPackages.ps1 -PackageVersion 1.1.0 -ExpectedCommit 63cde0bc360d5533cdce3982361f6aba86f71f58 -EnableCuda
./scripts/Test-PublishedPackages.ps1 -PackageVersion 1.1.0 -ConsumerFramework net10.0 -ExpectedCommit 63cde0bc360d5533cdce3982361f6aba86f71f58 -EnableCuda
```

## Evidence and promotion

Anonymized Windows validation covers .NET 9 and .NET 10 with real CUDA.
Debug and Release each pass 666 cases
on each runtime with real CUDA; Release also passes 666 per runtime with CPU
intrinsics disabled. Builds have zero warnings/errors and formatting passes.
CPU-only CI commands pass 587 cases per runtime and explicitly skip one hardware
marker on each. Candidate release tag and prerelease-type positive/negative checks pass.
Fresh candidate consumers and unchanged baseline-compiled consumers pass CPU/CUDA
checks on both runtimes. All three packages pass SDK baseline validation.

An isolated intentionally incompatible Core package changes Reset by adding an
optional parameter, removing the original binary signature. Packing is rejected
with CP0002 against published 1.0.0; the real source and package output are not
mutated. This verifies the compiled-package guard independently of source API
inventories. No compatibility diagnostic is suppressed.
