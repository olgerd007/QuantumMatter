# QuantumMatter 1.4.0

QuantumMatter 1.4 combines explicit noise channels with mid-circuit measurement,
classical feedback and reset through a separate noisy dynamic workflow. Existing
unitary, noise and dynamic APIs retain their contracts.

## Install

Use matching package versions; Core is included transitively:

```sh
dotnet add package QuantumMatter.Application --version 1.4.0
dotnet add package QuantumMatter.Infrastructure --version 1.4.0
```

The [release record](1.4.0.md) tracks publication and validation evidence.

## Changes

- Build finite NoisyDynamicCircuit programs from snapshotted unitary segments,
  mapped measurements, mask/value conditions, reset and explicit channel placements.
- Preserve classical history across noise boundaries, including measurement overwrites.
- Reuse the existing bit-flip, phase-flip, depolarizing and amplitude-damping channels.
- Run a fresh quantum/classical history for each shot and return immutable classical counts.
- Inspect one conditional trajectory without implicit readout or an ensemble ket.
- Evolve an existing state with explicit unitary/noise backend injection.
- Consume the new APIs through a separate package sample alongside unchanged baseline,
  observation and dynamic consumers.

The 15 additive declarations bring the shipped API inventory to 255, preserving all
240 existing declarations. Library assets remain net9.0 for .NET 9/10 consumers;
assembly binding stays 1.0.0.0 and file version is 1.4.0.0. No new runtime dependency,
backend port or result type is introduced.

## Conventions and limits

Quantum and classical register widths are each 1–30. Bit zero is least significant;
classical labels print the highest bit first. Channels act on the current conditional
state and leave classical memory untouched. Counts represent only explicit final
classical memory, with no implicit terminal readout or ensemble FinalState.

Noise, measurement, reset selection and classical decisions run on the host. CUDA
executes unitary segments with existing upload/download boundaries and resource
budgets. Conditional noise, loops, arbitrary classical expressions, correlated
channels, automatic noise insertion and device-resident noisy feedback are outside
this release. CPU support covers Windows/Linux x64; CUDA support covers Windows x64,
with Linux CUDA experimental. See the [noisy dynamic guide](../noisy-dynamic-circuits.md),
[API additions](../api/1.4.0.md) and [compatibility policy](../compatibility.md).

## Validation

The implementation passes all eight Windows/Linux Debug/Release runtime CI jobs.
Local hardware-enabled suites pass 763 tests per runtime/configuration on an
compatible CUDA device. CPU-only suites pass 677 tests plus one explicit hardware skip.
Independent dense Kraus/projector oracles verify supported channel/measurement
branches, phases, feedback, reset and classical-conditioned density matrices.
Exact branch enumeration verifies interleaved histories and classical overwrites.
Stable local Debug/Release builds pass without warnings or errors, with all 763
CUDA-enabled cases per runtime/configuration and formatting verification passing.
All four fresh stable-package consumers and unchanged 1.0.0-compiled consumers pass
on .NET 9/10, including CUDA. Promotion CI and public-feed evidence are tracked in
the release record.
