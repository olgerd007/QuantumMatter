# v1.8 development candidate

Candidate: **1.8.0-rc.1**, prepared **2026-10-27** in the existing development
branch, including the earlier unpublished v1.7 work. This work does not tag,
publish or deploy the candidate. See the [security lab guide](../authenticated-pqc.md)
and [changelog](../../CHANGELOG.md).

## Implementation and boundaries

- Server-authenticated ephemeral ML-KEM-768 exchange using a provisioned
  ML-DSA-65 public-key pin. Clients remain anonymous.
- Canonical transcript binding, separately derived confirmation/traffic keys,
  bidirectional confirmation, ordered bounded AES-GCM records and owned key disposal.
- An in-process round trip and 17 explicit rejection checks, with separate tests
  for framing, trust snapshots, KEM-key substitution, nonce/counter limits,
  cancellation and strict CLI policy.
- Additive --session, --strict and repeatable --require switches. Unsupported or
  missing required algorithms fail with a nonzero exit code.
- Dedicated security CI with a digest-pinned native-provider container and
  anonymous report validation. Existing runtime CI remains in place.

These are internal types in the existing net10.0 lab. No project, runtime
dependency or public SDK declaration is added. Library targets remain net9.0,
assembly binding stays 1.0.0.0 and package validation keeps the reviewed 1.0.0
baseline. Existing v1.7 quantum experiments and discovery-mode reports are retained.

## Security assumptions

The NIST section 5.2.3 example supplies the high-level exchange pattern. Pin-based
trust provisioning, framing, confirmation and records are explicit lab adaptations,
not a reviewed production or interoperable protocol. There is no socket service,
certificate chain, mutual client authentication, key-update protocol, persistent
key store, side-channel assessment or full security certification. Endpoint and
provider compromise remain outside this experiment. Tests are correctness evidence
under the documented model, not a protocol-security proof.

## Validation on 2026-10-27

- Restore and full Debug/Release builds pass with zero warnings/errors.
- Complete CPU-only Debug suites: **939 net9.0**, **962 net10.0**, with one
  explicit CUDA-suite skip per runtime.
- Complete real-CUDA Release suites: **1,030 net9.0**, **1,053 net10.0**,
  with no skipped cases.
- All 23 focused PQC tests pass on the local native provider and inside the exact
  digest-pinned SDK container used by the security job. The container executes
  the Linux/OpenSSL path, including strict session execution and privacy checks.
- Strict runs on both provider environments complete the bidirectional exchange
  and reject all 17 adversarial cases. This is separate execution on each
  platform, not a cross-provider protocol-interoperability certification.
- The actual CLI returns 3 for a required unsupported optional algorithm and 2
  for an unknown requirement. A process-level regression confirms fresh report
  directories are created, report-write failures return 5, and both successful
  output and write-failure diagnostics omit absolute host paths.
- Formatting, candidate version/tag guard, relative links, report privacy and
  diff whitespace checks pass. The existing default quantum demo still runs.
- Fresh local package checks pass for both consumer runtimes: all five isolated
  consumers, packaged CUDA execution and unchanged binaries compiled against
  published 1.0.0. The package checker also requires the v1.8 guide/release record.
