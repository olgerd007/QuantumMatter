## Scope and contracts

Core/Dynamic adds a separate finite DynamicCircuit model with unitary snapshots,
ordered measurement mappings, mask/value conditions and stochastic single-qubit
reset. StateVector.EvolveDynamic returns one execution's classical register.
Application/Dynamic supplies independent trajectory execution and immutable final
classical counts. Counts have no implicit quantum readout or ensemble FinalState.
See the [dynamic-circuit guide](../dynamic-circuits.md) for mathematical contracts.

All 218 existing shipped declarations, net9.0 library assets, the 1.x assembly binding
version and published 1.0.0 package-validation baseline remain unchanged. The 22
reviewed additions are promoted from Unshipped to Shipped, giving 240 declarations. No runtime
dependency or new backend port is added. Noise/dynamic composition, loops and
device-resident classical control are outside this increment.

## Validation

Baseline before implementation: restore and all 704 Debug hardware-enabled cases
pass on both .NET 9 and .NET 10 in an anonymized CUDA-capable environment. The
historical candidate evidence below is supplemented by stable promotion and
tagged-source publication checks. Local package checks alone do not establish
public publication.

Candidate validation on Windows x64 with the project-selected SDK and .NET 9/.NET 10:

- Restore and Debug/Release builds pass with zero warnings or errors.
- Debug and Release each pass 734 tests per runtime with real CUDA enabled.
- Release with CPU intrinsics disabled also passes 734 tests per runtime.
- CPU-only Release passes 653 tests and one explicit hardware-suite skip per runtime.
- Formatting verification and scalar, SIMD-selected and CUDA dynamic demos pass.
- All three packages validate against published 1.0.0; all 218 shipped declarations
  and earlier package-consumer sources were unchanged in the candidate. Stable promotion freezes all 240 declarations.
- Fresh .NET 9/10 baseline, observation and dynamic consumers pass CPU/SIMD/CUDA
  checks. Package hashes match the freshly packed candidate artifacts.
- Unchanged 1.0.0-compiled consumers pass with candidate DLLs on each runtime,
  including CUDA; their binary/dependency hashes are preserved.
- The updated public-feed script still validates published 1.2.0 observation and
  existing APIs on .NET 10 with real CUDA and exact source metadata.
- All 25 Markdown files' relative links and git diff --check pass.

Teleportation tests force every classical branch using analytic supported-basis
midpoint draws, then compare complex receiver amplitudes without phase alignment.
Independent dense Kraus matrices verify reset on each target through three qubits.
Exact branch enumeration verifies interleaved measurements/feedback/reset and
seeded shot distributions with a bound exceeding six worst-case standard deviations.

```powershell
dotnet restore QuantumMatter.sln
dotnet build QuantumMatter.sln --no-restore -c Debug -p:EnableCudaTests=true
dotnet test QuantumMatter.sln --no-build --no-restore -c Debug -p:EnableCudaTests=true
dotnet build QuantumMatter.sln --no-restore -c Release -p:EnableCudaTests=true
dotnet test QuantumMatter.sln --no-build --no-restore -c Release -p:EnableCudaTests=true
dotnet format QuantumMatter.sln --no-restore --verify-no-changes
./scripts/Test-Packages.ps1 -Configuration Release -SkipBuild -EnableCuda
./scripts/Test-Packages.ps1 -Configuration Release -SkipBuild -ConsumerFramework net10.0 -EnableCuda
```

Test-Packages.ps1 must run separate sibling PackageConsumer, ObservationConsumer
and DynamicConsumer projects from fresh packages. PackageConsumer remains limited
to 1.0.0 APIs and also runs unchanged baseline-compiled binaries with candidate
SDK DLLs. Test-PublishedPackages.ps1 offers -ValidateDynamicCircuits for
1.3 packages; omit that option for older public versions. It does not publish.
