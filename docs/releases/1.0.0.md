## Scope

The release packages the reviewed v0.1–v0.7 implementation as Core, Application
and Infrastructure. It adds API inventories, complete XML documentation, centralized
package metadata, package-asset validation, a clean package-only consumer and CI
checks. Gate identifiers and existing signatures/defaults remain intact. See the
[versioned API reference](../api/1.0.0.md), [compatibility policy](../compatibility.md)
and root CHANGELOG.md included in every package.

Invalid basis indices now use ArgumentOutOfRangeException rather than exposing
array IndexOutOfRangeException. This pre-stable behavioral correction has regression
tests and is called out in the changelog. It does not alter valid state evolution.

## Reproducible local verification

```powershell
dotnet restore QuantumMatter.sln
dotnet build QuantumMatter.sln --no-restore -c Release
dotnet test QuantumMatter.sln --no-restore -c Release
dotnet format QuantumMatter.sln --no-restore --verify-no-changes
./scripts/Test-Packages.ps1 -Configuration Release
```

Package checks build/pack three libraries with SDK package validation, verify
metadata, XML/API/docs/license/symbol assets and dependency boundaries, then restore
an isolated sample with no project references. A unique package cache, source
mapping and SHA512 comparisons prove the sample uses newly produced artifacts.
The consumer executes scalar/parallel gates, complex phases, algorithms, budgets,
cancellation and noise. Optional -EnableCuda tests the packaged CUDA backend on
real hardware and fails when CUDA is unavailable.

Use -ConsumerFramework net10.0 to run the same net9.0 artifacts on .NET 10 (requires
a .NET 10 SDK); the script selects that SDK only inside the isolated consumer.
The repository libraries/SDK selection remain unchanged. Both consumer modes are
configured in Windows/Linux Release CI. NVIDIA workflow dispatch requires a
maintainer-managed Windows x64 runner labelled quantummatter-gpu. It never runs
automatically on pull requests. v1.0 CUDA support is limited to Windows x64;
Linux CUDA remains experimental and is excluded from the supported release matrix.

Artifacts are under artifacts/packages; the clean consumer and its cache remain
under artifacts/package-smoke for inspection. These directories are gitignored.
Local builds omit source-commit links because this checkout may contain uncommitted
files; CI builds can produce deterministic source metadata from the reviewed commit.
Committed-source validation confirms repository commit metadata and embedded
portable-PDB Source Link mappings for all three libraries at commit
0c64bb882f862751c3127d134bd55a6073eccef2. The Windows/Linux CI run below also passes.

The [release notes](1.0.0-notes.md) are ready for the v1.0.0 GitHub Release.

Publishing a GitHub Release triggers the workflow. The tag must exactly match the
committed Version with a leading v; prerelease flags must match the version suffix.
Windows/Linux validation and both package consumer frameworks must pass first.
The publish job downloads the tested Linux artifacts, obtains a short-lived token
through NuGet/login and pushes packages/symbols. It does not rebuild different
artifacts after validation. A normal commit/push/PR cannot trigger publication.
Hardware validation and the documented framework/support policy apply to promotion.
