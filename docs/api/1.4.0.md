# QuantumMatter 1.4.0 API additions

Version 1.4 adds 15 declarations to the 240 declarations shipped through
[1.3.0](1.3.0.md), for a total of 255. Exact nullable annotations, parameter names,
defaults and signatures are frozen in the Core/Application PublicAPI.Shipped.txt
files and included in packages alongside XML documentation.

## QuantumMatter.Core.Dynamic

NoisyDynamicCircuit(int qubits, int classicalBits) accepts register widths in [1,30].
QubitCount, ClassicalBitCount and StepCount are read-only. Its fluent builders are:

| Member | Contract |
| --- | --- |
| Append(QuantumCircuit circuit) | Snapshots a size-compatible unitary segment |
| If(int classicalMask, int expectedValue, QuantumCircuit circuit) | Snapshots a segment executed when (register & mask) == value |
| Measure(ReadOnlySpan&lt;int&gt; qubits, ReadOnlySpan&lt;int&gt; classicalBits) | Copies ordered mappings and overwrites classical destinations |
| Reset(int qubit) | Inserts measurement/conditional X without writing classical bits |
| ApplyNoise(NoiseChannel channel, int target) | Places an unconditional single-qubit channel at this exact program position |

Noise leaves stored classical history intact. Subsequent conditions read that
history even when noise changes an earlier measured qubit. Zero-strength noise
invokes no noise backend and consumes no draw. StepCount counts explicit instructions,
including channel placements, rather than internal execution segments.

StateVector.EvolveNoisyDynamic(NoisyDynamicCircuit circuit,
IStateVectorBackend unitaryBackend, INoiseChannelBackend noiseBackend, Random random,
CancellationToken cancellationToken = default) evolves one existing quantum state
and returns its packed classical register. Classical memory starts at zero for each
public call. Cancellation or backend failure can leave partial state changes and
does not return a successful classical result.

## QuantumMatter.Application.Dynamic

NoisyDynamicStateVectorSimulator(IStateVectorBackend unitaryBackend,
INoiseChannelBackend noiseBackend, SimulationOptions? options = null) uses caller-owned
backends and a positive host amplitude-array budget.

- SimulateTrajectory(NoisyDynamicCircuit circuit, int? seed = null, CancellationToken cancellationToken = default)
  returns the existing DynamicTrajectoryResult with one conditional state and classical outcome.
- Run(NoisyDynamicCircuit circuit, int shots = 1024, int? seed = null, CancellationToken cancellationToken = default)
  returns the existing DynamicSimulationResult with immutable final classical counts.

Every shot starts from fresh quantum/classical state and executes the whole history.
There is no implicit terminal readout or ensemble FinalState. The 15 additions
include type, constructor, method and property-getter declarations; no result type,
backend port, runtime dependency or existing public signature changes.

See the [noisy dynamic guide](../noisy-dynamic-circuits.md) for Kraus conventions,
stochastic uncertainty, resource budgets, failure behavior and host/device boundaries.
