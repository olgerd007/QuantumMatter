# QuantumMatter 1.3.0 API additions

Version 1.3 adds 22 declarations to the 218 declarations shipped through
[1.2.0](1.2.0.md), for a total of 240. Exact nullable annotations, parameter names,
defaults and signatures are frozen in the Core/Application PublicAPI.Shipped.txt
files and included in packages alongside XML documentation.

## QuantumMatter.Core.Dynamic

DynamicCircuit(int qubits, int classicalBits) accepts register widths in [1,30].
QubitCount, ClassicalBitCount and StepCount are read-only. Its fluent builders are:

| Member | Contract |
| --- | --- |
| Append(QuantumCircuit circuit) | Copies a size-compatible unitary segment |
| If(int classicalMask, int expectedValue, QuantumCircuit circuit) | Copies a segment executed when (register & mask) == value |
| Measure(ReadOnlySpan&lt;int&gt; qubits, ReadOnlySpan&lt;int&gt; classicalBits) | Copies ordered mappings; overwrites selected classical destinations |
| Reset(int qubit) | Inserts a measurement/conditional-X trajectory without writing classical bits |

StateVector.EvolveDynamic(DynamicCircuit circuit, IStateVectorBackend backend,
Random random, CancellationToken cancellationToken = default) returns the packed
classical register while evolving an existing quantum state. Classical memory
starts at zero for each call. Cancellation/failure can leave partial state changes.

## QuantumMatter.Application.Dynamic

DynamicStateVectorSimulator(IStateVectorBackend backend, SimulationOptions? options = null)
uses caller-owned backends and a validated host amplitude-array budget.

- SimulateTrajectory(DynamicCircuit circuit, int? seed = null, CancellationToken cancellationToken = default)
  returns DynamicTrajectoryResult with FinalState, ClassicalBitCount and ClassicalOutcome.
- Run(DynamicCircuit circuit, int shots = 1024, int? seed = null, CancellationToken cancellationToken = default)
  returns DynamicSimulationResult with ClassicalBitCount, Shots and immutable Counts.

Result constructors are internal. Each shot executes the full program from fresh
quantum/classical state. Counts represent only explicit final classical memory;
there is no implicit terminal measurement or ensemble FinalState.

The 22 entries include type declarations, constructor/member declarations and
property getters. The original unitary/noise APIs and backend interfaces are
unchanged. See the [dynamic guide](../dynamic-circuits.md) for masks, ordering,
reset Kraus operators, random draws, cancellation and memory costs.
